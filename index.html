The finding that shaped the tool

The strongest preference signal still needed human examples.

In my creative-text experiments, the strongest automated preference signals depended on human-labeled examples for the same writing prompt.

Those findings shaped Idea Search: preserve the judgment and its context so they can inform the next search.

What makes the memory modular?

Separate pieces of guidance, each with a source, a scope, and a decision.

A critique becomes a collection of instructions you can inspect and choose for another search. The original judgment remains available beside the accepted guidance.

01 / Separate

One idea per entry.

Preserve a physical transformation, keep the product legible, or avoid competing tricks. Each instruction can be reviewed on its own.

02 / Select

Choose the context for the next search.

The application offers all accepted memory, selected entries, or no memory for a batch. This record uses all four accepted entries.

03 / Trace

Keep the conditions of judgment.

Entries retain their scope, strength, source candidate, feedback, and approval history. The receipt shows where the instruction came from.

From selector experiments to Idea Search.

The research motivated the design. The walkthrough demonstrates its mechanics.

Research observation

Useful preference signals depended on local human examples.

The creative-text experiments found the strongest automated signals with human-labeled responses to the same prompt. Specific comparisons preserved a preference boundary that averaging the reference set lost. Cross-prompt controls did not establish a general creative evaluator.

Explore the findings and controls

Engineering response

Give judgment a durable, inspectable form.

Idea Search preserves concrete alternatives, natural-language critique, and individual decisions about what should guide future work. Reuse is explicit: the person chooses which accepted instructions fit the next search.

Reusing guidance is a design choice that can be inspected. Its usefulness on a new prompt or project still needs to be judged.

Keep the reasoning inside the reaction.

“More like this” can mean its material, pacing, feasibility, or emotional effect. A natural-language critique can explain the distinction. Idea Search keeps that wording beside the candidate it refers to.

Make generalization a human decision.

A complaint about one crowded concept is not necessarily a ban on its colors. Accepting, editing, and rejecting proposals lets the person decide which lessons should outlive the example.

Know what the next search inherited.

A batch records the accepted memory supplied to generation and its fingerprint. The ledger and receipts connect that context to the judgments and decisions that created it.

I built the complete local application: candidate and batch versioning, prompt assembly, feedback analysis, memory decisions, generation handoffs, and their provenance records. This public showcase presents one recorded loop.

Architecture, source evidence, and limitations

What this page is

A static projection of one recorded session, laid out in the product’s own cockpit geometry. It is not the running React application: the recipe controls, Generate key, and decision buttons show recorded values and do nothing.

The model drafts prompts. You decide what carries forward.

Idea Search was originally developed as Subjective Skill Studio. The evidence remains tied to that application’s audited source snapshot. The public showcase is named Idea_Search_Showcase; the application source remains private.

Architecture

FastAPI + SQLite backend (async), React + Vite + TypeScript frontend, no component framework. A two-layer prompt assembly (meta-prompt → candidate template) feeds both the recipe preview and generation, with fingerprints over the accepted-memory corpus and the generation recipe deciding whether a new candidate appends to the current batch or starts a new one. This showcase drives the same FastAPI app in-process through TestClient using the project’s built-in mock provider — the identical code path a hosted LLM provider would run, with deterministic, non-networked output.

The creator problem

Creative feedback usually disappears between rounds: it stays in the creator’s head, a chat transcript, or an isolated note. Idea Search attaches that reasoning to the exact candidate being judged, and makes only explicitly approved guidance available to later generation.

What Eduardo built

The complete local application: batch and candidate versioning, recipe and meta-prompt assembly, natural-language feedback, proposal decisions, accepted-memory injection, optional artifact and rendering workflows, and the ledger, timeline, fingerprints, backlinks, and receipts that make the loop auditable.

Fixture scope & evidence

This deterministic walkthrough proves the application’s persistence, approval, scoping, and provenance mechanics. Its candidate prompts and memory proposals are a curated script returned by the built-in mock provider, not output from a hosted model, so nothing here demonstrates content-sensitive proposal quality or improved creative outputs.

The recorded candidate text, judgments, memory decisions, and stamps come from evidence/fixture/loop.json, generated by evidence/generate_fixture.py against source snapshot commit 82ed65dc01c2 (extraction root 04906b0, backend schema v4). Raw database ids and timestamps are non-deterministic by construction (uuid4, wall-clock); the generator canonicalizes them into stable tokens before writing evidence, so re-running it against the same snapshot reproduces byte-identical files.

Limitations

  • The candidate text and the drafted proposals are a curated, deterministic script returned by the built-in mock provider, not output from a hosted LLM — the walkthrough demonstrates control flow and the data model, not generation quality.
  • A product demonstration on synthetic data: not a benchmark, not evidence of production usage.
  • The interactive React/Vite frontend is not deployed here. This page reads the same backend output the UI would render and lays it out in the same cockpit geometry, but nothing on it is live.
